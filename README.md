# 游戏策划协作体系（Game Design System）

> 一套**可复用的专业游戏策划工作方式**：把模糊创意变成能交付 AI 开发、能验收的策划案。
> 适用于任何类型、任何引擎（Godot / Unity / UE / 自研）。与 AI 协作开发配合使用。

## 这套体系解决什么

| 痛点 | 解法 |
|---|---|
| 想法模糊，AI 只能"自由发挥" | `TEMPLATE.md` 提供结构化策划案骨架，逐节引导 |
| 设计决策没人记录，下次会话全忘 | `adr/` 决策记录（ADR）+ 跨会话续接规则 |
| 一次问 10 个问题，用户崩溃 | `PROCESS.md` 分阶段、每次 1~3 个问题 |
| 功能做出来没人验收 | 每项功能配"验收标准"，AI 按标准自检 |
| AI 替人拍板核心玩法 | 明确分工：AI 出选项和草案，人做方向决策 |

## 文件结构

```
game-design-system/
├── README.md          ← 本文件（总览）
├── TEMPLATE.md        ← 专业策划案母版：每个游戏复制一份，逐节填写
├── PROCESS.md         ← 协作流程：阶段确认门、备选分析、评审、ADR、续接规则
├── CONFIRM.md         ← 阶段确认稿规范：每阶段结束产出，用户确认后前进
├── FINAL.md           ← 正式策划案规范：定稿后生成带版本/封面/确认的正式稿
├── knowledge/         ← 游戏设计知识库（方法论卡片+案例拆解+术语表）
└── adr/
    └── _template.md   ← 决策记录模板（复制后命名 0001-xxx.md）
```

## 怎么用（三个场景）

### 场景 A：新游戏创意落地（含阶段确认门）
1. 复制 `TEMPLATE.md` 为 `<游戏>/docs/DESIGN.md`
2. 按 `PROCESS.md` 的阶段顺序（0→6）逐节推进，每阶段 1~3 个问题
3. **每阶段结束：产出确认稿**（`docs/confirmations/`，按 `CONFIRM.md` 规范）→ **用户确认后才进下一阶段**
4. 每个决策带备选分析（选项+利弊+推荐），确认稿归档
5. 定稿后按 `FINAL.md` 生成正式策划案（`docs/策划案.md`，v1.0）

### 场景 B：日常功能开发
1. 设计定稿后加载 `ai-game-dev` 技能（单功能迭代：设计→实现→运行→验证→提交）
2. 每个新功能先在 DESIGN.md 写一节（做什么 + 验收标准），再做
3. 重大设计变动走 ADR（`adr/000N-xxx.md`）

### 场景 C：换电脑 / 新会话续接
1. 读 `docs/DESIGN.md` 的"设计进度"小节 + `docs/confirmations/` + `adr/` + `git log`
2. 复述进度给用户确认（"阶段 X 确认稿待确认 / 已确认"），从"下一步"继续
3. 设计决策一律查 ADR / 确认稿，不靠对话记忆

## 与 AI 协作的基本原则

- **文件即真相**：所有重要信息写入项目文件，不依赖对话记忆
- **设计先行**：动手写代码前先有设计文档
- **人机分工**：AI 负责结构、选项、草案、代码；人负责方向、体验、品味
- **小步走**：一次一个可验证的小功能，做完→测试→提交→下一个
