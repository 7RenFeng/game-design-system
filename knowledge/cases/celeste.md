# 案例拆解：Celeste（蔚蓝）

> 平台跳跃手感与关卡设计的标杆。可借鉴：手感打磨流程、模块化关卡、死亡即教学。

## 项目速览

- 类型：精确平台跳跃（2D）
- 规模：A 级独立游戏，8 章 + B/C 面，约 700+ 房间
- 卖点：**极致的跳跃手感** + 登山叙事的心理隐喻
- 核心体验目标：挑战 + 掌控感 +（轻）叙事

## 设计拆解

### 1. 手感（Game Feel）——它是怎么"手感这么好"的
- **可变跳高**：跳跃高度由按住时长决定——玩家对垂直空间有完全控制
- **超宽松容错**（coyote time 土狼时间 + jump buffer 跳跃缓冲）：离开平台后 ~0.1s 仍可跳、落地前 ~0.1s 按跳仍生效——**手感好 = 容错宽**，让玩家觉得自己很强
- **调参流程**：开发者在原型期把参数（重力/加速/跳跃力）做成一键可调，实机狂调
- **教训**：手感不是"调出来的数字"，是"调参流程 + 容错设计"的产物

### 2. 关卡（Level Design）——模块化 + 教学即设计
- **一个机制一章**：每章引入一个新机制（冲刺/抓墙/泡泡…），深度挖掘后进入下一章
- **阶梯教学**：安全演示 → 组合 → 压力测试，每关结尾有"考卷房间"
- **死亡即教学**：死了 1 秒重生，重试成本为零，玩家把失败当"解题"
- **屏幕内可见**：关卡布局让玩家"看到目的地"，路径可读性高

### 3. 难度曲线（Flow）
- 登山隐喻 = 难度曲线：每章攀登比前一章更高，但每章内部有平台期/喘息点
- B/C 面：给硬核玩家的焦虑区内容，主线保持心流通道

## 可借鉴到本协作流程

| Celeste 做法 | 对应到我们的流程 |
|---|---|
| 手感=调参流程+容错 | 阶段 4 数值表写"↑/↓ 影响"；原型期一键调参 |
| 一个机制一章 | 功能清单按"机制-章节"分组，MVP 只含 1 个核心机制 |
| 死亡即教学 | 难度设计时标注"失败后的学习路径" |
| 屏幕内可见 | 评审关卡布局时查"玩家能否预见下一步" |
