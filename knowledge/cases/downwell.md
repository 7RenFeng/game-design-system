# 案例拆解：Downwell（井下冒险）

> "一个机制做到极致"的极简典范。可借鉴：单一机制的深度挖掘、手感即卖点、克制的内容量。

## 项目速览

- 类型：Roguelike 纵向平台跳跃（单屏竖版）
- 规模：独立游戏，一人开发（Moppin），Unity 引擎
- 卖点：**只有两个操作（左右移动+下落中射击）却极其上瘾**
- 核心体验目标：挑战 + 掌控感 + 发现

## 设计拆解

### 1. 单一机制（One Key Mechanic）
- 整个游戏围绕一个核心动作：**下落中射击**（gunboots 枪靴）
- 所有系统（敌人/宝石/商店/升级）都挂在这个核心动作上，没有旁支系统
- **教训**：GDC 专门讲《Designing Downwell around one key mechanic》——先找到一个机制，把它的深度挖穿

### 2. 手感即卖点
- 下落+射击的组合有强烈"节奏感"：连续命中产生连击，combo 是核心爽点
- 重力/射击频率/判定宽度都围绕"连击流畅度"调优
- **教训**：卖点不是一个"玩法类型"，而是**一个具体的、手感上的爽感**

### 3. 内容克制
- 敌人/道具种类极少，但通过组合和随机生成产生变化
- 短局（10-20 分钟）→ 高重玩率：死得干脆，再来一把成本低

### 4. MVP 思维（对我们最重要）
- Downwell 的 MVP 就是最终游戏：核心动作 + 一个敌人 + 计分 = 已经好玩
- 后续内容（宝石商店/升级）是**围绕已验证的核心体验**加的，不是一开始堆的

## 可借鉴到本协作流程

| Downwell 做法 | 对应到我们的流程 |
|---|---|
| 单一机制挖深 | 阶段 1 循环设计：先定"一个核心动作"，再扩展 |
| MVP=核心体验已好玩 | 阶段 3 MVP 定义：先让 1 个机制好玩，再谈内容量 |
| 手感即卖点 | 阶段 0 卖点 = 具体手感爽感，不是类型标签 |
| 内容克制 | 阶段 5 内容规划：用组合数代替内容数 |
